# jsonrepair-rs 0.2.2

This patch release improves truncated LLM output repair and adds reliability
and performance evidence.

## Fixed

- Plus-prefixed exponent-only tokens such as `+e1` are rejected instead of
  producing invalid JSON (#65).
- A JSON string cut off at the first slash of a URL-like value, such as
  `{"content":"https:/`, now repairs to valid JSON. This also works through
  the reader-to-writer API when the input arrives in small chunks.

## Added

- A second fuzz target checks equivalence between string and chunked-reader
  repair, valid output, and no partial writes on repair failure. A scheduled
  GitHub Actions job runs both fuzz targets weekly.
- The CLI benchmark report can compare the optimized Rust binary against the
  Python `json-repair` CLI on the same input cases. The report states the
  measurement boundary and package/runtime versions.

## Compatibility

No public API or error type changed. The reader-to-writer API still buffers
the full input and output internally. Benchmark results compare whole CLI
invocations, not parser-only calls, and do not imply identical repair choices.
