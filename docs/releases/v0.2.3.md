# jsonrepair-rs 0.2.3

The first GitHub Actions fuzz run for 0.2.2 found a parser loop on input
containing `[` followed by a form feed character. The parser now returns an
error for unsupported whitespace-only array values instead of repeatedly
adding output until memory is exhausted. A regression test covers form feed
at the start of an array and after an array item.

A separate fuzz case found that root-level value-list repair could remove an
earlier separator while trying to roll back a trailing comma. The rollback is
now limited to the separator added for the unfinished value.

An invalid backslash escape followed by a control character now emits an
escaped JSON character instead of an invalid raw control byte.

Escaped commas followed by ambiguous quotes no longer cause recursive string
repair retries and stack overflow.

An empty fenced value after another root value no longer leaves a trailing
comma in the repaired root list.

This patch is source-compatible with 0.2.2 and does not change public APIs or
error types. The 0.2.2 improvements to truncated LLM JSON, fuzz coverage,
and Python CLI comparison remain included.
