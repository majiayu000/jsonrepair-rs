# jsonrepair-rs 0.2.6

This release includes the content repair options delivered in PRs #84–#86 and
adds input byte budgets to the existing options helpers.

## Content policy

`with_preserve_comment_markers(true)` keeps comment-like Markdown and code in
malformed tool arguments. `with_decode_unquoted_escapes(true)` independently
interprets complete JSON escapes in unquoted keys and values. Both remain off by
default. Leave decoding off for literal Windows paths. The policies preserve
existing regex/wrapper and URL boundaries and do not enable arbitrary multiline
unquoted content. Strict mode retains precedence. See
[the option contracts](../repair-options.md).

## Input byte budget

Use `.with_max_input_bytes(limit)` to reject oversized input before repair.
String/writer/serde options helpers use `JsonRepairErrorKind::InputTooLarge`
through their existing repair-error wrappers. Reader helpers consume at most
`limit + 1` bytes and return `JsonRepairStreamError::InputTooLarge { limit }`.
They do not repair an artificially truncated prefix and do not call the writer
on oversize, read or repair failure. Read and write failures retain their IO
error categories; write failure can leave partial output.

Accepted input and repaired output remain fully buffered. Reader helpers wait
for EOF; the byte budget does not bound read time or total parser/output memory.
Invalid UTF-8 below the limit remains a `Read` error. An oversized bounded
buffer returns the limit error before UTF-8 validation. Defaults remain
unlimited; zero and maximum `usize` limits are supported.

## Integration and validation

Run `cargo run --example tool_arguments` for a synthetic completed-string repair
example with explicit content options and a byte budget. The tool owner must
still parse and validate the candidate. Existing downstream provenance and
application boundaries remain in [downstream compatibility](../downstream-compatibility.md).
No downstream workspace migration or production acceptance is claimed.

`tests/bounded_input_tests.rs` checks exact byte limits, limit+1 consumption,
UTF-8/chunk boundaries, untouched writers on errors, policy composition and
possible partial output on write failure. Existing content and parser tests
remain unchanged. Release verification follows
[the repository checklist](../release-checklist.md), including Rust 1.70 core/CLI
CI and package/publish dry-run verification. Execution results belong to the
implementation PR.
